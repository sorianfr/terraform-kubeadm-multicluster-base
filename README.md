# terraform-kubeadm-multicluster-base

End-to-end guide for this repository: what it builds, how the pieces fit together, and how to deploy, operate, and tear it down.

---

## 1. What this project does

This project provisions **multiple self-managed Kubernetes clusters on AWS** using:

| Layer | Tool | Role |
|-------|------|------|
| AMI | Packer | Pre-bakes kubeadm, kubelet, kubectl, containerd |
| Infra + bootstrap | Terraform | VPC, bastion, per-cluster private subnet, control plane EC2, worker ASG, IAM, Secrets Manager, userdata |
| Day-0 cluster join | cloud-init userdata | `kubeadm init` on CP; workers pull join command and `kubeadm join` |
| Day-1 platform | Ansible (on bastion) | kubeconfigs, Calico, Helm, AWS CCM, Istio multi-cluster mesh, EBS CSI |

Default layout (from `terraform.tfvars`):

- **cluster1** — private subnet `10.0.2.0/24`, CP `10.0.2.10`, pods `10.244.0.0/16`, services `10.96.0.0/16`
- **cluster2** — private subnet `10.0.3.0/24`, CP `10.0.3.10`, pods `10.245.0.0/16`, services `10.100.0.0/16`

Each cluster has:

- 1 fixed private IP control-plane EC2
- Worker Auto Scaling Group (`worker_min` / `desired` / `max`)
- Optional **AWS Cloud Controller Manager** (`enable_aws_ccm = true`)
- Join token stored in **AWS Secrets Manager** as `{cluster_name}/comando-unir`

Shared resources (one per deploy):

- VPC + public subnet + IGW
- Shared NAT Gateway (private nodes egress)
- Bastion in the public subnet (SSH jump host + Ansible runner)

Kubernetes version used in userdata today: **v1.31.14**.  
Istio version set via Terraform → Ansible group vars: **1.28.0**.

## 2. High-level architecture

```
                         Internet
                            │
                     ┌──────▼──────┐
                     │     IGW     │
                     └──────┬──────┘
                            │
              ┌─────────────┴──────────────┐
              │     Public subnet          │
              │  10.0.1.0/24               │
              │  • Bastion (SSH + Ansible) │
              │  • NAT Gateway (shared)    │
              └─────────────┬──────────────┘
                            │
         ┌──────────────────┴──────────────────┐
         │                                     │
┌────────▼─────────┐                 ┌─────────▼────────┐
│ Private subnet   │                 │ Private subnet   │
│ cluster1         │                 │ cluster2         │
│ 10.0.2.0/24      │                 │ 10.0.3.0/24      │
│ CP 10.0.2.10     │                 │ CP 10.0.3.10     │
│ Workers (ASG)    │                 │ Workers (ASG)    │
└──────────────────┘                 └──────────────────┘
```

- Control planes and workers have **no public IPs**; outbound goes through the shared NAT.
- You reach nodes via **bastion SSH** (or SSM if configured; SSM is attached to workers but Default Host Management may still warn on console).
- Clusters share one VPC so they can talk for **Istio multi-cluster** (east-west), while pod/service CIDRs stay unique.

## 4. Prerequisites

- AWS account credentials configured (`aws` CLI / env / profile)
- Terraform ~> AWS provider 5.x
- Packer (to build or refresh the node AMI)
- An existing Packer AMI matching filter `k8s-base-*` owned by your account (module looks up `most_recent`)
- Local tools: `ssh`, `scp`
- Enough quotas for EC2, EIP, NAT Gateway, ASG instances in the target region (default `us-east-1`)

Optional:

- Session Manager plugin (if you prefer SSM over SSH)
- Helm / kubectl locally (mainly used on the bastion)

## 5. Packer AMI (nodes)

Control planes and workers do **not** use `var.ami_id` from root. They use:

```hcl
data "aws_ami" "k8s_base" {
  most_recent = true
  owners      = ["self"]
  filter {
    name   = "name"
    values = ["k8s-base-*"]
  }
}
```

Build once (or when you want a newer base):

```bash
cd packer
packer init .
packer build ami.pkr.hcl
```

`setup_k8s_ec2.sh` roughly:

- Disables swap / UFW
- Enables bridge/netfilter sysctls
- Installs and configures **containerd** (systemd cgroup)
- Installs **kubeadm / kubelet / kubectl** (Kubernetes packages)

The bastion uses a separate `var.ami_id` (generic Ubuntu) and installs Ansible + kubectl via Terraform `remote-exec`.

## 6. Terraform: shared infrastructure

Root `main.tf` creates:

1. **TLS key pair** → AWS key pair + local `k8s-key.pem` (mode `0600`)
2. **VPC** (`var.vpc_cidr_block`, default `10.0.0.0/16`)
3. **Public subnet** + IGW + public route table
4. **Shared NAT** (EIP + NAT GW in public subnet) + shared private route table (`0.0.0.0/0` → NAT)
5. **Bastion** EC2 in public subnet with SG allowing SSH `22` from `0.0.0.0/0` (tighten for production)
6. **EBS CSI IAM** role/profile (`AmazonEBSCSIDriverRole`) — also referenced by modules for mounting policy
7. **`module.clusters`** — one instance of `modules/kubeadm_cluster` per entry in `var.clusters`
8. Generated Ansible assets:
   - `ansible/inventory/hosts.yml`
   - `ansible/group_vars/all.yml`
   - `ansible/group_vars/<cluster>.yml`
9. Provisioners:
   - Copy `k8s-key.pem` (and any `copy_files_to_bastion`) to bastion
   - Copy `ansible/` to bastion
   - `update_ssh_config.sh` (path is Windows/WSL-oriented; harmless skip/adjust if unused)
   - **`null_resource.run_ansible`** → `./run_ansible_on_bastion.sh <bastion_dns>`

### Configure clusters

Edit `terraform.tfvars`:

```hcl
clusters = [
  {
    name                      = "cluster1"
    private_subnet_cidr_block = "10.0.2.0/24"
    controlplane_private_ip   = "10.0.2.10"
    instance_type             = "c7i-flex.large"
    worker_min                = 2
    worker_max                = 4
    worker_desired            = 2
    pod_cidr                  = "10.244.0.0/16"
    service_cidr              = "10.96.0.0/16"
    network                   = "network1"   # Istio network name
    enable_aws_ccm            = true
  },
  # ...
]
```

Important fields:

| Field | Meaning |
|-------|---------|
| `controlplane_private_ip` | Static private IP for the CP ENI |
| `pod_cidr` / `service_cidr` | Must not overlap across clusters |
| `network` | Istio `topology.istio.io/network` label / mesh network id |
| `enable_aws_ccm` | External cloud-provider flags in kubeadm + CCM Helm install |
| `worker_*` | ASG sizing (capacity only; Cluster Autoscaler is optional / not automated) |

## 7. Per-cluster module (`modules/kubeadm_cluster`)

For each cluster the module creates:

| Resource | Purpose |
|----------|---------|
| Private subnet | Tagged for Kubernetes / internal ELB |
| Security group | SSH from bastion, API 6443, kubelet, Calico, NodePorts, Istio ports, self traffic |
| Secrets Manager secret | `{name}/comando-unir` (placeholder then real join command) |
| Control-plane IAM | Secrets write, CCM/ELB/EC2/ASG policies, EBS CSI |
| Worker IAM | Secrets read, same CCM/ASG/EBS policies, SSM core |
| `aws_instance.control_plane` | Fixed private IP + userdata `kubeadm init` |
| Launch template + ASG | Workers with userdata `kubeadm join` |

Subnet tags include `kubernetes.io/cluster/<name>=owned` so CCM/ELB discovery works.

ASG also has Cluster Autoscaler discovery tags (`k8s.io/cluster-autoscaler/enabled` and `.../<name>=owned`). Installing CA itself is **manual** (see `CLUSTERAUTOSCALER.md`); ASG alone does not auto-scale pods.

## 8. Node bootstrap (userdata)

### Control plane (`control_plane_userdata.sh.tpl`)

Runs at first boot via cloud-init:

1. Prefer IPv4 in `/etc/gai.conf` (NAT Gateway has **no IPv6**; registry pulls otherwise hang)
2. Wait until `https://registry.k8s.io/v2/` answers over **IPv4** (`curl -4` **without** `-f` — registry often returns HTTP 401, which is still “reachable”)
3. If `enable_aws_ccm`:
   - Set kubelet `--cloud-provider=external` + `provider-id`
   - Write kubeadm `ClusterConfiguration` / `InitConfiguration` for external CCM
4. `kubeadm config images pull` then `kubeadm init`
5. Install kubeconfig for user `ubuntu`
6. Create a long-lived join token and write it to Secrets Manager
7. Touch `/var/log/user_data_done.log`

Success marker:

```bash
cat /var/log/user_data_done.log
ls /etc/kubernetes/admin.conf
```

Live log:

```bash
sudo tail -f /var/log/cloud-init-output.log
```

### Workers (`worker_userdata.sh.tpl`)

1. Configure external cloud-provider + provider-id
2. Wait until CP API `:6443` is open
3. Poll Secrets Manager until join command ≠ `waiting-for-controlplane`
4. `kubeadm join` with containerd CRI socket
5. Restart kubelet

Workers therefore **self-join** once the CP has published the secret — no Ansible step required for joining.

## 9. Ansible day-1 pipeline

Triggered automatically by Terraform (`run_ansible`), or manually:

```bash
./run_ansible_on_bastion.sh <bastion_public_dns>
```

On the bastion this runs, in order:

| # | Playbook | What it does |
|---|----------|--------------|
| 1 | `1_fetch_kubeconfigs.yml` | Pull admin kubeconfigs from each CP |
| 2 | `2_normalize_kubeconfigs.yml` | Normalize cluster/user names |
| 3 | `3_merge_kubeconfigs.yml` | Merge into `~/.kube/config` (contexts `cluster1`, `cluster2`, …) |
| 4 | `4_untaint_nodes.yml` | Wait for API; remove `node.cloudprovider.kubernetes.io/uninitialized` |
| 5 | `5_install_calico.yml` | Install Calico CNI on all clusters |
| 6 | `6_install_helm.yml` | Install Helm on bastion |
| 7 | `7_install_aws_ccm.yml` | Helm-install AWS CCM where `enable_aws_ccm` is true |
| 8 | `8_install_certs.yml` | Shared Istio root CA, per-cluster intermediate, `istioctl install`, east-west gateway, expose services, remote secrets |
| 14 | `14_install_ebs_csi_driver.yml` | AWS EBS CSI + default gp3 StorageClass |

Playbooks use inventory generated from Terraform and SSH ProxyJump through the bastion to private control planes.

### Istio multi-cluster (role `certs`)

Summary of what playbook 8 installs:

1. Download Istio `istio_version` (from `group_vars/all.yml`, currently `1.28.0`)
2. Generate **one root CA** + **intermediate per cluster** (`make -f tools/certs/Makefile.selfsigned.mk …`)
3. Create `istio-system` + `cacerts` secret on each cluster
4. Label `istio-system` with `topology.istio.io/network=<network>`
5. `istioctl install` with shared `meshID: mesh1` and distinct `clusterName` / `network`
6. Wait for istiod; install **east-west gateway** (retried)
7. Expose services + create **remote secrets** so clusters discover each other

East-west gateways typically create **AWS LoadBalancers**. Those ENIs/LBs **block VPC destroy** unless removed first — see destroy section.

## 10. Deploy from scratch

```bash
# 1) Build AMI (once)
cd packer && packer init . && packer build ami.pkr.hcl && cd ..

# 2) Configure clusters
cp terraform.tfvars.example terraform.tfvars   # or edit existing terraform.tfvars

# 3) Apply
terraform init
terraform apply
```

Apply timeline (approximate):

1. VPC / NAT / bastion (~few minutes)
2. Control planes boot → userdata waits for registry → `kubeadm init` (~3–5+ minutes per CP)
3. Workers poll Secrets Manager and join
4. Files + Ansible copy to bastion
5. Ansible pipeline (Calico → CCM → Istio → EBS) — can take a long time; Istio east-west is often the longest

Useful outputs:

```bash
terraform output bastion_public_dns
terraform output clusters
terraform output kubeconfig_locations
```

SSH:

```bash
ssh -i k8s-key.pem ubuntu@$(terraform output -raw bastion_public_dns)
kubectl config get-contexts
kubectl --context cluster1 get nodes -o wide
kubectl --context cluster2 get nodes -o wide
```

## 11. Day-2 operations

### Re-run Ansible only

If Terraform infra is fine but Ansible failed midway (common: apt lock on bastion during Istio certs):

```bash
# On bastion: wait for unattended-upgrades
while sudo fuser /var/lib/dpkg/lock-frontend >/dev/null 2>&1; do sleep 15; done

./run_ansible_on_bastion.sh $(terraform output -raw bastion_public_dns)
```

Or SSH in and run individual playbooks under `~/ansible`.

### Verify AWS CCM

```bash
kubectl --context cluster1 -n kube-system get ds aws-cloud-controller-manager
kubectl get nodes -o custom-columns=NAME:.metadata.name,PROVIDERID:.spec.providerID,STATUS:.status.conditions[-1].type
```

Nodes should show `providerID` like `aws:///us-east-1b/i-...` and lose the cloud-uninitialized taint after playbook 4 / CCM.

### LoadBalancer Services

Require CCM + IAM (module already allows `iam:CreateServiceLinkedRole` for ELB). If LB creation fails with `AccessDenied` on that action, ensure the service-linked role exists or CP role policies are attached.

### Cluster Autoscaler

Not installed by the automated pipeline. Tags on the ASG are prepared; follow `CLUSTERAUTOSCALER.md` if you want horizontal node autoscaling.

## 12. Destroy / teardown

**Always uninstall Istio before `terraform destroy`.** East-west / ingress `LoadBalancer` Services leave AWS ELBs and ENIs that hold the VPC/IGW.

```bash
./uninstall_istio.sh
# or
./uninstall_istio.sh $(terraform output -raw bastion_public_dns)
# or on bastion:
./uninstall_istio.sh --local
```

Then:

```bash
terraform destroy
```

If destroy still sticks on ENIs/LBs, check leftover ELBs/target groups tagged for your clusters and delete them, wait for ENI release, retry destroy.

## 13. Known pitfalls

| Symptom | Cause | Mitigation |
|---------|--------|------------|
| CP userdata hangs / ImagePull `i/o timeout` | IPv6 preferred; NAT is IPv4-only | `gai.conf` IPv4 preference + registry wait (already in userdata) |
| Registry wait never succeeds with `curl -f` | `registry.k8s.io/v2/` returns **401** | Use `curl` **without** `-f` (current template) |
| Ansible fails installing `make`/`gcc` | Bastion `unattended-upgrades` holds dpkg lock | Wait for lock; re-run Ansible; optionally add apt retries in `roles/certs` |
| `terraform destroy` fails on IGW/VPC | Istio LBs still attached | Run `uninstall_istio.sh` first |
| Workers stay NotReady / no CNI | Ansible Calico not run yet | Ensure playbook 5 completed |
| Nodes stay tainted `cloudprovider.../uninitialized` | CCM / untaint not done | Playbooks 4 and 7 |
| SSM console errors on CP | SSM role / Default Host Management | Ignore if using bastion SSH; workers have SSM core policy |

## 14. Security notes (lab vs production)

This repo is oriented to **lab / learning** multi-cluster setups. Tighten before production use:

- Bastion SSH open to `0.0.0.0/0` → restrict to your IP / VPN
- Prefer SSM Session Manager and lock down SSH
- Rotate / protect `k8s-key.pem`; it is written locally and copied to bastion
- Join tokens use `--ttl 0` (non-expiring) for automation convenience — shorten in production
- IAM CCM policies are broad (`Resource = "*"` for many EC2/ELB/ASG actions) — scope down per environment
- Single AZ by default — not highly available control planes
